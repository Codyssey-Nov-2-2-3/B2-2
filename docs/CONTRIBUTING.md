## 충돌 대응 흐름

1. 충돌이 발생하면 `git status`로 충돌 파일을 확인한다.
2. PR 작성자는 관련 팀원에게 충돌한 파일과 각자의 변경 의도를 공유한다.
3. PR 작성자가 관련 팀원과 협의하여 양쪽 변경을 합칠지,
   한쪽을 선택할지, 새로 수정할지 결정한다.
4. 충돌 내용을 수정하고 충돌 마커를 제거한다.
   파일 이동·삭제 충돌은 파일 경로와 보존할 내용을 함께 확인한다.
5. 수정한 문서의 내용과 링크를 확인하고,
   Python 예제가 있다면 Python 3.10+에서 실행한다.
6. 해결한 파일을 `git add <파일경로>`로 스테이징한다.
   삭제하기로 합의한 파일은 `git rm <파일경로>`로 반영한다.
   `git status`로 미해결 충돌이 없는지 확인한 뒤,
   merge 진행 중이라면 `git commit`으로 병합을 완료한다.
7. 작업 브랜치에 push하고 PR에서 다시 리뷰를 요청한다.

### 담당자와 기록 위치

- 해결 담당: 충돌이 발생한 PR의 작성자
- 협의 대상: 충돌한 내용을 작성한 팀원
- 기록 위치: `docs/conflict-resolution.md`

### 기록할 내용

- 참여자와 역할
- 충돌이 발생한 브랜치, 파일, 상황
- 충돌 마커 원문(`<<<<<<<`, `=======`, `>>>>>>>`)
- 선택한 해결 전략과 이유
- 실제 실행한 명령어와 해결 절차
- 해결 결과 및 관련 PR·커밋 링크
- 배운 점과 예방 방법

파일 이동·삭제 충돌처럼 충돌 마커가 없는 경우에는
그 사실과 `git status` 및 충돌 메시지를 기록한다.

### 주의 사항

- 다른 팀원의 변경 내용을 확인 없이 삭제하지 않는다.
- 공유 브랜치에서 강제 push나 rebase로 히스토리를 재작성하지 않는다.
- 충돌 해결은 작업 브랜치에서 수행하고 PR을 통해 main에 반영한다.
